# 安全公告：历史发布包中的个人信息（PII）

> **状态**：已接受风险（历史不可撤回） · **影响对象**：moonmux 0.2.0–0.9.1 历史发布包与 git 历史 ·
> **当前版本**：v0.9.3 已干净 · **最近复核**：2026-11-13
>
> 本公告记录 moonmux 历史版本中作者个人信息（PII）泄露事实、影响面、不可撤回约束、风险接受决定与后续门禁。
> 相关文档：[`docs/known-issues.md`](../known-issues.md) KI-03、[`RELEASING.md`](../../RELEASING.md) 发布检查单、
> [`docs/releases/v0.9.3.md`](../releases/v0.9.3.md) §6（已知问题/残余风险）与 [`CHANGELOG.md`](../../CHANGELOG.md)。

## 2. 影响面

1. **旧版本发布包**：mooncakes.io 上 `WangYF0829/moonmux` 的 0.2.0–0.9.1 仍可被 `moon add` 下载，包内 `项目申报书.md` 含上述联系方式。
2. **git 历史**：公开仓库历史提交仍含该内容；即使当前分支已清理，历史可被检索/克隆。
3. **性质**：为作者本人的联系方式，**不涉及密码、token、私钥、客户数据或第三方数据**；风险类别为隐私/骚扰类，
   而非凭据泄露导致账号接管；不改变当前版本的任何功能/完整性。
4. **版本完整性**：PII 只存在于文档文件；各版本代码/制品本身未受影响，历史包与 tag 仍可按原 sha256 校验（不因该问题改写）。

## 3. 不可撤回约束

- **mooncakes 不支持删除或撤回单个版本**（同一版本号不可重发；重复发布会返回 409 `duplicated`）。
- 唯一止损工具是 `moon deprecate <module>`（**全模块弃用**），代价是所有版本不可再 `moon add`，影响所有使用者 → **不采用**。
- **不重写 git 历史**（`git filter-repo` 等）：会改变既有 commit/tag 哈希，破坏已发布制品与 tag/记录的可复现链条，
  且无法撤回已下载内容 → **不采用**。
- 因此该问题只能以"历史事实 + 风险接受 + 后续门禁"的方式登记处理。

## 4. 风险接受

- **决定**：接受历史 PII 风险，不因该问题弃用模块或重写历史；以发布前扫描门禁 + 公开说明防回归。
  （决策依据：数据为作者本人联系方式、非凭据；mooncakes 无单版本撤回；`docs/releases/v0.9.3.md` §6 与 `CHANGELOG.md` 已记录。）
- **残余等级**：低—中（隐私类；公开可检索，但无账号/资金风险）。
- **适用边界**：接受仅针对 0.2.0–0.9.1 历史包与既有 git 历史；**当前及未来版本必须保持 0 命中**，不适用风险接受。
- **说明义务**：面向使用者的发布记录/README 相关章节可引用本公告；旧版本使用者被建议升级到 0.9.3+。

## 5. 后续门禁（强制）

1. **发布前必跑**：`bash scripts/check_pii.sh`（当前工作树，退出码必须为 0）——见 [`scripts/check_pii.sh`](../../scripts/check_pii.sh)。
   检查手机号/邮箱/QQ/身份证四类规则（带数字边界减少误报，输出脱敏定位）。
2. **发布审计（可选）**：`bash scripts/check_pii.sh --history` 记录历史命中情况（**预期非 0**，仅作审计留档，不设硬门禁）。
3. `RELEASING.md` 发布检查单已包含该项（"敏感信息 / PII 扫描"）；CI 建议对当前树执行同一脚本（由 CI 组接线）。
4. **防回归约定**：新增文档/提交不得包含个人联系方式；测试数据、NOTICE/THIRD_PARTY 等文档同样适用；联系方式统一走 GitHub Issue。
5. 如未来法务/隐私要求升级：评估联系 mooncakes 官方询问旧版本下架可行性（工具链无单版本撤回能力）——仅在明确要求时启动，
   并在 `docs/known-issues.md` KI-03 更新决策记录。

## 7. 复核方式

```bash
# 当前树（发布门禁，必须 0 命中）
bash scripts/check_pii.sh
# 历史审计（预期非 0；仅留档，不阻断发布）
bash scripts/check_pii.sh --history
# 复核历史发布包（示例：本地注册表缓存 zip）
ls ~/.moon/registry/cache/WangYF0829/moonmux/
```

复核频率：每次发布前；每季度随依赖维护性评估一并复核（见 [`docs/dependency-assessment.md`](../dependency-assessment.md)）。
负责人：项目维护者（风险接受决策）+ 发布负责人（门禁执行）。
