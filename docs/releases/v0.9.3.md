## 6. 已知问题 / 残余风险（发布基线）

- `to-wav` 的第三方解码器（`LL728/moonvorbis@0.1.4`）对恶意码流仍可能有内存安全问题；v0.9.3 的解码前 gate 只覆盖已识别的畸形头，**不要把 `to-wav` 直接暴露给不可信输入**（修复轮的加固状态见 CHANGELOG `[Unreleased]`）。
- MP4 解封装样本数上限 1,048,576（约 5.8 小时 @20 ms 包）。
- `@fs` 无 stat / inode / rename：覆盖已有输出时的整体读入内存与中断窗口无法彻底消除。
- 历史发布包 0.2.0–0.9.1 含 PII（0.9.2 起已清理）——已作为不可撤回的历史风险接受，不因此全模块 deprecate；后续发布前必须执行 PII 扫描（见 `RELEASING.md` §1）。

```console

Would deprecate WangYF0829/moonmux@0.9.2: 演练：验证弃用预览流程，不实际执行
…（0.9.1 / 0.9.0 / 0.8.0 / 0.7.1 / 0.7.0 / 0.6.0 / 0.5.0 / 0.4.0 / 0.3.2 / 0.3.1 / 0.3.0 / 0.2.0 同样输出）…
$ echo $?
0
```

- **结果**：exit 0；逐版本打印「Would deprecate …」，共 14 个已发布版本（0.2.0–0.9.3，0.1.0 未发布到 mooncakes）。
- **确认未修改注册表**：演练后 `moon view WangYF0829/moonmux --json` 全部版本仍为 `"yanked": false`。
- **结论**：回滚预案中「全模块弃用」的预览路径可用；真实弃用仅用于严重事件（见 `RELEASING.md` §6 的处置矩阵），且发布负责人须先完成本预览并保存输出。
- **限制**：MoonBit 只能**全模块**弃用、不能撤回单个版本；弃用不影响版本解析，但依赖解析选中被弃用模块时会告警。
