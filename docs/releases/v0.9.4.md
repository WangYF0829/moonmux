## 5. 可复现性

- 发布包由 `moon package` 从当前工作树生成；工作树含 `.gitattributes`（`eol=lf`），发布前按 `RELEASING.md` 规范化。
- v0.9.3 实测经验：**保留作者工作区字节**可复现旧 zip；标准 checkout 因 4 个文本文件换行差异（LICENSE / README.md / docs/architecture.md / scripts/smoke.sh）不可逐字节复现。v0.9.4 记录本次实测结论：发布包为原工作区字节（520,040 B / sha256 `07fc5b70…8033`）；标准 checkout 的 LF 规范化差异同 v0.9.3，未做逐字节复现声明。
- 工具链版本固定版本下载 URL 上游 403（见 `docs/dependency-assessment.md` §4.3），故以「latest + 每次构建记录 `moon version --all`」补偿。

## 6. 本版要点（验收整改）

- **Vorbis gate v3**：解码前完整 setup 有界校验（codebook / floor / residue / mapping / mode / 交叉引用 / lookup / ordered / framing）+ 内存分配上界 + CPU 双预算（IMDCT + Huffman，含 residue VQ 码字数）；RT-A/RT3/RT4 系列 PoC 全部 exit 1、0 崩溃、0 残留。
- **CLI / 解析边界**：demux 文件对象上限、split 段数上限、回滚告警、退出码契约、Windows 长路径/errno 诊断。
- **CI 11 job**：新增 api-diff（`--target-all`）、examples、publish-dry-run；API 文档覆盖门禁、库层/总覆盖率门禁（总 ≥80%）。
- **测试与覆盖率**：native 475 / wasm-gc 425 / js 425；工具口径总覆盖率 82.87%、库层 91.79%、未覆盖行 635。
- **发布治理与证据**：RELEASING、NOTICE/THIRD_PARTY、发布记录、冷装抽样（30/30）、依赖维护性评估、known-issues、PII 风险接受、SBOM/PII/包内容脚本、preflight_release。

## 9. 发布后 CI 修复记录（2026-11-13，仅测试/脚本/CI，无库行为变更）

首跑失败 3 项均为 CI/测试基础设施问题，而非产品缺陷，修复如下（`master` 后续提交）：

| # | 失败 job | 根因 | 修复 | 影响 |
|---|---|---|---|---|
| 1 | check · fmt · info · test (ubuntu) | `cmd/main/main_wbtest.mbt` 的 `normalize_path` 用例只按 Windows 语义断言（大小写/反斜杠/尾随点折叠），POSIX 下行为不同 | 测试改为按 `windows_paths()` 分支断言 Windows / POSIX 两种语义（native 全平台） | 测试代码，无库行为变更 |
| 2 | install · moon add | `moon new` 生成的工程默认 `preferred_target = "wasm"`，与 0.9.4 的 `supported_targets = [native, wasm-gc, js]` 不兼容 → `moon check` 失败（install 循环误判为"包尚未上线"） | `scripts/install_check.sh` 在干净工程内切换 `preferred_target = "native"` 并显式 `moon check --target native` | 发布/验证脚本，无库行为变更 |
| 3 | publish · dry-run precheck | CI runner 无 mooncakes 登录凭据（`moon login` 只在发布者本地），dry-run 必然失败 | 无凭据时跳过并输出 `::warning::`（同时增加 `Registry login is required` 兼容分支）；本地发布前由 `scripts/preflight_release.sh` 覆盖 dry-run 语义 | CI 配置，无库行为变更 |
