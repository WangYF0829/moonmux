## 1. 方法

每份样本按用户文档的标准流程执行，四步全部成功才算成功：

```powershell
cd <samples>\sNN
moon new --user qa --name qa sNN        # 全新工程（项目目录外）
cd sNN
moon add WangYF0829/moonmux@0.9.3       # 冷装依赖（解析 @0.9.3 及其传递依赖）
moon check                              # 编译检查
# 最小示例：cmd/main 导入 @moonmux 并打印版本，然后运行
moon run --target native cmd/main
```

- 最小示例代码（写入生成工程的 `cmd/main/main.mbt`，`moon.pkg` 增加 `import { "WangYF0829/moonmux" }`）：

```moonbit
fn main {
  println(@moonmux.describe())
  println("version=" + @moonmux.MOONMUX_VERSION)
}
```

- 判定标准：四步退出码均为 0，且运行输出同时包含 `moonmux 0.9.3` 与 `version=0.9.3`。
- 重试规则（不隐瞒失败）：任一步非 0 时记录原始 stderr 并立即重试 1 次（间隔 0.8s），重试结果作为该步最终结果；本次 30 样本**零失败、零重试触发**。
- 耗时由 PowerShell `Stopwatch` 按步计时（毫秒，向下取整），不包含 `moon new` 后写最小示例文件的时间（<10ms）。

## 7. 局限（如实登记）

1. **无法真正清空本机 registry 缓存**：本机 `~\.moon` 全局 registry 索引与包缓存由多个并行团队任务共享，清空会破坏其它任务且不可恢复；因此本轮只能做「工程级冷装」（全新工程 + 全新工程内 `.mooncakes` + 固定版本 `@0.9.3` 解析），无法验证「全新机器、空 registry、纯网络下载」。日志中 30/30 的 `Using cached` 是这一局限的直接证据。
2. **样本目录偏离任务指定路径**：任务要求 `C:\Users\lenovo\Desktop\moonbit\_verify\install-sample`，但本会话沙箱为 workspace-write 且无法提权，写该路径被拒绝（Access denied）；改用 DSH 会话临时目录 `%TEMP%\dsh-ZTGYAs\moonmux-install-sample\run`。命令、判定与环境完全一致，且样本均在 moonmux 项目目录之外，不污染发布包。
3. **平台单一**：仅 Windows x64 抽样；Linux/macOS 未覆盖（如需可移植性结论，应在对应平台各重复 30 次）。
4. **工具链/网络版本固定**：moon 0.1.20261012 与 registry 现有索引快照；后续发布若升级工具链或索引结构变化，需重跑本抽样。
5. `moon new` 符号链接警告（见 §5）属 Windows 权限限制；不影响 `moon add/check/run`。
